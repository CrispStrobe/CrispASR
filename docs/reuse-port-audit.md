# RE-USE independent implementation and license audit

This audit is scoped to the revisions linked below, not every file or release
in these projects. It concerns the NVIDIA NemotronLabs RE-USE offline model;
the original and streaming models have different terms and must be identified
separately. No source from these four implementations was copied into the
experimental CrispASR port. See the [reference audit](reuse-reference-audit.md)
for methods, limits, and measured comparisons.

The pinned [NVIDIA checkpoint and model materials](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-RE-USE/blob/31f82f2efad1095034492f236e8dac9239ba713b/LICENSE) carry OpenMDW-1.1 and original third-party notices. These terms are distinct from the repository licenses above and from CrispASR's MIT license. In particular, copying an MIT or Apache implementation does not change the terms of the model weights. At audio.cpp's audited source revision its documented default model is the older noncommercial RE-USE checkpoint; its later [model repository](https://huggingface.co/audio-cpp/RE-USE-GGUF) separately identifies the NemotronLabs conversion. File names and checkpoint provenance must be checked before comparison or distribution.

## Findings for the port

* The independent ONNX network matched our Python reference at selected encoder, block, decoder and waveform boundaries when both received identical 100 ms input spectra. The network comparison excludes the frontend and NVIDIA's fused CUDA kernels. Our CUDA run using NVIDIA's original SEMamba and Mamba's **unfused** reference separately supports the Python adapter's network math. The native full-waveform comparison still fails for that short input.
* speech.cpp's one-second output differed by 0.103% relative RMS from the Python CPU reference for one public-audio excerpt, compared with 2.70% for the tested 100 ms excerpt. This argues for testing representative durations in addition to short clips; it does not establish general quality. The native experimental diff now supports one-second windows and keeps intermediate and waveform gates.
* NVIDIA's chunked inference and speech.cpp use five-second windows with 50% overlap and normalized overlap-add. RE-USE Audio's Android path uses a different four-second window and overlap policy. Because the model includes instance normalization and bidirectional recurrence, whole-file and differently chunked inference need separate comparisons; they cannot be assumed equivalent.
* speech.cpp requests full precision for its custom Mamba operation to avoid intermediate overflow. Its ggml fork provides an operation absent from our pinned ggml, so adopting that graph requires implementing and testing the operation and supported backends, not merely converting weights. Metal work is deferred.
* Raw phase around the ±π branch cut is model input, not just a display choice. RE-USE Audio's PocketFFT proof reports bitwise parity on its tested environment; on our x86/PyTorch 2.11 environment its proof failed its first nine-frame synthetic case, with maximum complex error 2.13e-6 and 64 phase branch flips. This is an environment-specific observation, not a verdict on its Android results. Compare the actual magnitude and raw phase as well as final audio across platforms.
* Qualify the implementation with independent audio, multiple durations and sample rates, silence and impulse boundaries, float input and quantized input, full intermediate captures, and chunk transitions. Include C ABI and binding coverage before calling it a supported backend. Check fused NVIDIA CUDA separately when the required extensions are available.

The Rust build attempt on the available network-mounted build storage failed while executing Cargo build scripts with `Invalid argument`; it is an unverified source review here, not an independently run Rust result.
