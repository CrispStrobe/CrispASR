# backend-components.txt — runtimes in src/ that are SUB-MODULES, not backends.
#
# Read by tools/check-backend-wiring.py. It exists to close the last blind spot
# in that audit: a runtime that is in NEITHER the CLI roster NOR the c_api list
# is invisible to all three existing checks — exactly the state
# mel-band-roformer was in while being the default `--separate` model.
#
# The obvious signal for that fourth check — "src/*.h declares
# <x>_init_from_file but no backend is named <x>" — fires on 20 of 82 stems, and
# 17 of those are legitimate components. A gate with 17 false positives trains
# everyone to ignore the audit, which is worse than no gate. So each component
# is listed here ONCE, with its consumer, and the check fails on anything not
# named. "This is a sub-module, not a backend" becomes a recorded decision
# instead of a silent omission.
#
# NOT listed here, deliberately: canary-ctc, irodori-tts and t5-translate. Those
# ARE backends, reachable under an alias, and the script's existing cli_resolves()
# probe asks the binary rather than guessing. Allowlisting them would hide a real
# regression if the alias ever broke.
#
# Adding an entry is a claim you should be able to defend: the runtime is driven
# by another backend or by a non-`--backend` surface, and it is not something a
# user selects with `--backend <x>`. If it IS user-selectable, wire it up
# instead — that is what the audit is asking for.
#
# Format: one stem per line (the `<x>` in `<x>_init_from_file`), '#' comments.

# --- Audio codecs / vocoders driven by a parent TTS backend ---
