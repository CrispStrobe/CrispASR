# CSM original forward-step timing diagnostic

This private, GPU-only diagnostic follows the [accepted CSM paired v2 result](../../../docs/csm-original-t4-benchmark-2026-10-29.json). It uses the same pinned Sesame `Model` and `Generator`, CSM checkpoint, Llama tokenizer, Mimi checkpoint, F32 CUDA placement, text, speaker 0, empty context, seed 1234, temperature 0.9, top-k 50 and 10,000 ms cap. SilentCipher watermarking remains an explicit identity call with **no watermark weights loaded**, as in v2. The v0.8.47 CUDA archive is used only for the same pinned Parakeet ASR quality judge; the native CSM engine is not measured here.

The first `generate_frame` call sends the full tokenized text through the backbone; each later call sends one preceding audio frame. Every attempted frame calls the backbone once and the depth decoder **31 times** for 32 codebooks: first depth input length two, then 30 inputs of length one. The Python generator checks all 32 sampled codebooks for EOS **after** `generate_frame` returns. The script records attempted calls, accepted audio frames, the EOS attempt and every observed module call. It requires one EOS attempt. These counts differ from v2's original 39 attempted frame calls and native 35 accepted frames; no step count is inferred from output duration.

`FrameProfile` wraps the actual `model.generate_frame` method. In the timing-on arm, `with_kwargs=True` hooks surround real `model.backbone` and `model.decoder` forwards, and a separate wrapper times Mimi `decode`. Every timed boundary synchronizes CUDA before and after. The frame timer includes embedding, projection and sampling as well as nested backbone/depth forwards. Nested forward durations include synchronization overhead and **must not be summed to estimate a frame**. The `generate_ms` timer includes prompt tokenization, frame generation, Mimi decode, identity watermark and resampling, but excludes model load, WAV save and ASR judging.

One warmup pair and three alternating measured pairs run on one loaded model. Seeds are reset before each generation and the official generator resets its caches. Both arms keep a minimal `generate_frame` wrapper to retain code tensors; only the timing-on arm adds synchronization and module hooks. The gate requires identical sampled-code hashes and WAV hashes across all eight calls, plus one EOS, correct call shapes/counts, process-specific GPU residency and positive SM activity observed during every generation, at least 1 GiB GPU residency, valid 24 kHz mono PCM and Parakeet WER ≤ 0.15 on every output. The timing-on/off difference is reported as profiling overhead evidence; it is not subtracted from individual steps. Raw WAVs and ASR logs remain under the **private** kernel output's `private-evidence/`; only a reviewed aggregate receipt is suitable for publication.

## Terms and scope

The [pinned Sesame source](https://github.com/SesameAILabs/csm/blob/836f886515f0dec02c22ed2316cc78904bdc0f36/LICENSE) and [CSM checkpoint card](https://huggingface.co/sesame/csm-1b) declare Apache-2.0, while CSM checkpoint access is gated. The [Llama tokenizer card](https://huggingface.co/meta-llama/Llama-3.2-1B) carries the separate Llama 3.2 license and access gate. The [Mimi checkpoint card](https://huggingface.co/kyutai/moshiko-pytorch-bf16) declares CC-BY-4.0; its full Moshi model card describes research-only intended use. [SilentCipher source](https://github.com/SesameAILabs/silentcipher/blob/d46d7d0893a583d8968ab3a6626e2289faec9152/LICENSE) is MIT, which does not establish rights to its separate model weights. The script checks pinned CSM and Llama card declarations and never redistributes weights, codes, audio or logs. Hosted access must already satisfy the applicable gates.

This measures the **original F32 path only**. The paired native Q4_K result differs in precision, RNG, frame trajectory and wrapper behavior. A separate source-built native diagnostic is required before even a scoped boundary comparison; no cross-engine per-step speedup follows from this result.
